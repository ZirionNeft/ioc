# Сравнение IoC-контейнеров и бенчмарки

[English version](bench.md).

Результаты получены 27 сентября 2026 года из текущего кода `@zirion/ioc` версии 3.0.0.

## Участники

| Контейнер | Сильная сторона | Существенное отличие |
| --- | --- | --- |
| [Awilix](https://github.com/jeffijoe/awilix) | Регистрация классов и функций, child scopes, disposer; подходит для Node HTTP-приложений. | Разрешение синхронное: промис фабрики не означает ожидания всех async-зависимостей графа. |
| [InversifyJS](https://inversify.io/docs/fundamentals/binding/) | Несколько bindings на token, constraints, decorators, sync и async разрешение. | `inRequestScope()` кеширует значение в одном дереве `get`, а не между вызовами в одном HTTP-запросе. |
| [TSyringe](https://github.com/microsoft/tsyringe) | Constructor injection, child containers, разные lifetimes. | Требует decorators и `reflect-metadata`; async-граф не ожидается автоматически. |

`@zirion/ioc` использует явный `inject` без decorators, поддерживает `getSync` и `get` с ожиданием async-графа, а также singleton, transient и request scope по объекту context. Один selector имеет одну регистрацию; нет `getAll`, named bindings, child containers и автоматического закрытия request/transient ресурсов. Подробности для переноса кода — в [руководстве по миграции](migration.ru.md).

## Методика

Платформа: macOS arm64, Node.js v24.19.0. Версии конкурентов закреплены в [lock-файле](../benchmarks/package-lock.json): Awilix 13.0.5, InversifyJS 8.2.3, TSyringe 4.10.0. Сборка `@zirion/ioc` использует `target: ES2022`. Регистрация контейнеров не входит в измерения A–C; их графы предварительно прогреты и проверены на правильное значение и lifetime. В D входят создание request scope, HTTP и сериализация ответа, но не запуск сервера.

Исходные измерения A–C используют **медиану** раундов; объединённые строки B дополнительно усредняют ширины 1/2/4. В D указано геометрическое среднее скоростей двух независимых прогонов. `await` и sync измеряются отдельно. Значения A и B — миллионы разрешений/с; в C единица зависит от строки; в D — HTTP-запросы/с. Разные сценарии нельзя сравнивать по абсолютной скорости: они выполняют разную работу.

## A. Базовый граф

Одно разрешение `Root → Leaf`: оба singleton либо оба transient. Для всех контейнеров выполняются 9 раундов по 200 000 разрешений; порядок участников меняется между раундами. Awilix использует `CLASSIC` injection. Числа — **млн разрешений/с**. [Код сценария](../benchmarks/compare.mjs).

| Lifetime / вызов | `@zirion/ioc` | Awilix | InversifyJS | TSyringe |
| --- | ---: | ---: | ---: | ---: |
| Singleton, `await` | 15.59 | 16.22 | 16.87 | 9.73 |
| Transient, `await` | 10.71 | 5.44 | 11.52 | 4.70 |
| Singleton, sync | 72.36 | 29.92 | 44.32 | 16.19 |
| Transient, sync | 9.43 | 6.55 | 11.20 | 4.96 |

`@zirion/ioc` лидирует в sync singleton, а InversifyJS — в transient. Этот сценарий измеряет прогретый поиск и создание простого графа, без async-фабрик и I/O.

## B. Ширина transient-графа

`Root` имеет 0, 1, 2 или 4 **независимые** зависимости. Каждый вариант проходит 9 раундов по 200 000 разрешений. Ширины 1/2/4 сведены в геометрическое среднее скоростей; исходные строки сохранены в JSON-выводе [бенчмарка](../benchmarks/compare-graphs.mjs). Числа — **млн разрешений/с**.

| Зависимостей | Вызов | `@zirion/ioc` | Awilix | InversifyJS | TSyringe |
| --- | --- | ---: | ---: | ---: | ---: |
| 0 | `await` | 12.97 | 10.96 | 13.58 | 7.57 |
| 0 | sync | 18.95 | 14.67 | 20.10 | 9.12 |
| 1/2/4, геом. среднее | `await` | 4.93 | 3.84 | 6.66 | 2.79 |
| 1/2/4, геом. среднее | sync | 5.02 | 4.04 | 6.45 | 2.85 |

На широких графах InversifyJS быстрее. Геометрическое среднее даёт каждой ширине одинаковый вклад. Форма классов в A и B различается, поэтому абсолютные скорости между этими таблицами напрямую не сопоставимы. [Тесты](../test/resolution-shapes.test.ts) отдельно проверяют порядок зависимостей, context, параллельные async-ветви и ошибки разрешения.

## C. Request scope

`Root → Leaf`, оба request-scoped. «Тот же запрос» — повторное разрешение уже созданного `Root` с одним context/child container, в **млн разрешений/с**. «Новый запрос» — создание scope и два разрешения с проверкой повторного использования, в **млн запросов/с**. Для каждого варианта выполнено 9 раундов по 200 000 операций. [Код сценария](../benchmarks/compare-request.mjs).

| Сценарий | Вызов | `@zirion/ioc` | Awilix | InversifyJS | TSyringe |
| --- | --- | ---: | ---: | --- | ---: |
| Тот же запрос | `await` | 14.80 | 11.06 | н/д | 9.44 |
| Тот же запрос | sync | 35.34 | 19.31 | н/д | 16.32 |
| Новый запрос | `await` | 1.52 | 0.79 | н/д | 2.03 |
| Новый запрос | sync | 1.34 | 0.77 | н/д | 2.34 |

InversifyJS здесь отмечен «н/д»: его `inRequestScope()` не разделяет значение между отдельными вызовами `get`. Это проверяется бенчмарком. Адаптер через дочерний контейнер возможен, но меняет способ регистрации; он измеряется в D.

## D. HTTP-запрос

[HTTP-бенчмарк](../benchmarks/compare-http.mjs) отправляет реальный `GET /products` через `fetch` на `127.0.0.1`. У всех контейнеров общий обработчик и одинаковый ответ: singleton-каталог и хранилище, request-метаданные языка, transient-сервис. Обработчик отдельно разрешает метаданные и сервис и проверяет, что сервис получил тот же request-экземпляр; клиент проверяет статус, язык, товары и `X-Request-ID`. Для InversifyJS создаётся дочерний контейнер на запрос, и его стоимость учтена.

Клиент и сервер работают в одном процессе, запросы идут **последовательно** по keep-alive соединению. В каждом из двух независимых прогонов: 200 прогревочных запросов, затем 7 раундов по 1500 запросов на контейнер. Скорость прогона рассчитана по медиане времени раундов; последний столбец — геометрическое среднее двух скоростей. Единица — **HTTP-запросов/с**.

| Контейнер | Прогон 1 | Прогон 2 | Геом. среднее |
| --- | ---: | ---: | ---: |
| `@zirion/ioc` | 700 | 696 | 698.0 |
| Awilix | 680 | 704 | 691.9 |
| InversifyJS | 676 | 712 | 693.8 |
| TSyringe | 692 | 723 | 707.3 |

**Вывод:** порядок лидеров поменялся между прогонами; различия средних меньше колебаний прогонов. Здесь нельзя заявить устойчивое преимущество одного контейнера. Время HTTP, `fetch` и JSON скрывает часть различий в DI. Это нормализованный маршрут по мотивам примера ниже: без чтения файла при первом запросе, случайного UUID и записи заказов. Параллельную нагрузку сценарий не измеряет.

## Итоговый балл

В каждой строке A–D лидер получает 100, остальные — `100 × скорость / скорость лидера`. Балл группы — среднее её строк: A, B и C содержат по 4 строки, D — одну. **Итог — среднее четырёх групп с равным весом**, вычисленное до округления строк и групп. Так разные единицы измерения не складываются напрямую. Балл показывает скорость в выбранных сценариях с учётом их покрытия, а не общий рейтинг качества контейнеров.

| Группа | `@zirion/ioc` | Awilix | InversifyJS | TSyringe |
| --- | ---: | ---: | ---: | ---: |
| A. Базовый граф | 92.4 | 60.8 | 90.3 | 41.3 |
| B. Ширина графа | 85.4 | 68.5 | 100.0 | 46.8 |
| C. Request scope | 83.0 | 50.3 | 0.0† | 77.5 |
| D. HTTP-запрос | 98.7 | 97.8 | 98.1 | 100.0 |
| Покрытие строк | 13/13 | 13/13 | 9/13 | 13/13 |
| **Итог** | **89.9** | **69.4** | **72.1**† | **66.4** |

† Отсутствующие четыре строки C считаются нулём **только в итоговом балле покрытия**. Это не нулевая скорость InversifyJS. На общих группах A, B и D его средний балл — 96.1.

## Воспроизведение и ограничения

Из корня репозитория:

```bash
yarn build
npm ci --prefix benchmarks
cd benchmarks
BENCH_ITERATIONS=200000 BENCH_ROUNDS=9 node compare.mjs
BENCH_ITERATIONS=200000 BENCH_ROUNDS=9 node compare-graphs.mjs
BENCH_ITERATIONS=200000 BENCH_ROUNDS=9 node compare-request.mjs
BENCH_ITERATIONS=1500 BENCH_ROUNDS=7 BENCH_WARMUP=200 node compare-http.mjs
```

Для D запустите последнюю команду дважды и возьмите геометрическое среднее `requestsPerSecond`. Бенчмарки выводят JSON; `compare-graphs.mjs` включает исходные результаты и поле `summaryResults`. Отдельно не измерялись холодный старт, частые регистрации, память, глубокие графы, параллельные HTTP-запросы и поддерживаемые версии Node. Async-фабрики и hooks проверены тестами, но не сведены в конкурентный бенчмарк из-за различий семантики. [V8 описывает ограничения синтетических бенчмарков](https://v8.dev/blog/real-world-performance).

## HTTP-пример со всеми scope

Работающее приложение: [сервер заказов](../benchmarks/http-orders.mjs) и [каталог товаров](../benchmarks/products.json). Оно создаёт один контейнер на сервер и новый context для каждого HTTP-запроса. Каталог читается асинхронной singleton-фабрикой при первом обращении; singleton-хранилище сохраняет заказы между запросами; `RequestMetadata` разделяется в пределах запроса; `OrderService` по умолчанию transient. `GET /health` использует синхронное разрешение.

```bash
yarn build
node benchmarks/http-orders.mjs
```

Проверенный запуск `createExampleServer()` дал: `GET /health` — 200 и 0 заказов; `GET /products` — 200 с русскими или английскими названиями согласно `Accept-Language`; `POST /orders` для двух порций кофе — 201, сумма 500; последующие `GET /orders` и `GET /health` показали созданный заказ. Неверный JSON вернул 400, неизвестный SKU — 404. У каждого ответа был свой `X-Request-ID`. Хранилище работает только в памяти процесса. Этот функциональный пример не следует смешивать с нормализованным HTTP-сценарием D.

Примеры интеграции на TypeScript для Node HTTP, Express и Fastify находятся в [каталоге examples](../examples/README.md).
